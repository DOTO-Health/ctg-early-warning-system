# Maintainers

This project currently has a single maintainer, who holds final decision-making authority and
merge rights, per [PROJECT_CHARTER.md § How decisions get made](./PROJECT_CHARTER.md#how-decisions-get-made).

## Current maintainer

| Name          | GitHub        | Contact                 |
| ------------- | ------------- | ----------------------- |
| Ramesh Mhalgi | @dotosoftware | software@dotohealth.com |

The maintainer is responsible for:

- Reviewing and merging all pull requests, including the extra review required for
  [classification-engine / guideline-rule changes](./PROJECT_CHARTER.md#how-decisions-get-made)
- Triaging issues and discussions
- Upholding the [Code of Conduct](./CODE_OF_CONDUCT.md)
- Deciding on new guideline support and major architectural changes via the RFC process described
  in [PROJECT_CHARTER.md](./PROJECT_CHARTER.md#how-decisions-get-made)

## Adding maintainers

As the project grows, additional maintainers may be added — typically based on sustained,
high-quality contribution in a specific area (e.g. the classification engine, the API, or
clinical/guideline review). There's no fixed process yet while the project has one maintainer;
this file will be updated with a table (name, area of ownership, contact) as the team grows.

## Stepping down / succession

If the current maintainer becomes inactive or wants to step back, this file should be updated
promptly — via a PR — to reflect a new maintainer or an explicit "seeking maintainer(s)" note,
rather than left pointing at stale contact info.
